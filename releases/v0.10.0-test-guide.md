# Workhub v0.10.0 사용자 테스트 가이드

실제 메일·메신저 발송은 아래에서 관리자가 선택해 켠 경우에만 시작합니다. 알림 기능은 배포 직후 사용 안 함입니다. 캡스 연동·파일 저장소 연결은 이번 범위에 포함하지 않습니다.

## 시작 위치
- 업무 현황 또는 캘린더 상단 → 일정·마감 관리
- 직접 주소: https://workhub.gunsystems.co.kr/work/schedule-control/
- 관리자 알림 설정: https://workhub.gunsystems.co.kr/work/schedule-control/policy/
- 일반 직원은 본인 수행 업무, 팀장·부서 관리자는 조회 가능한 팀 업무, 대표·본부장·관리자는 전사 조회 범위에 맞춰 표시됩니다. 결과 확인 의견은 본인 기록에 스스로 남길 수 없습니다.

## 1. 일정 변경 사유
1. 본인이 생성한 테스트 업무/교육 일정을 열고 업무 수정을 선택합니다.
2. 시작일 또는 수행 시간을 바꾸고 사유 없이 저장합니다. 사유 입력 안내가 나와야 합니다.
3. ‘교육기관 요청으로 일정 변경’ 등의 사유를 입력해 저장합니다.
4. 일정·마감 관리의 변경 이력에서 변경자·시각·사유·변경 전후를 확인합니다. 시작일이 당일/과거인 일정 변경은 별도 표시되며 최근 30일 변경 횟수가 누적됩니다.
5. 최초 마감일과 최초 등록 당시 일정은 이후 변경으로 덮어쓰지 않습니다. 기존 업무의 등록 시각은 소급 생성하지 않습니다.

## 2. 지연 등록
1. 시작일을 어제로 한 ‘간단 일정’을 신규 등록합니다. 자동 채워진 시작 시간도 확인합니다.
2. 일정·마감 관리 → 지연 등록 목록에서 해당 업무를 확인합니다.
3. 해당 수행자 계정으로 업무 상세 → 실시 결과·등록 사유 → ‘등록·변경 사유 설명’을 선택하고 이유를 남깁니다.
※ 같은 날짜의 시간은 5분 허용 간격을 두어 입력·저장에 소요되는 시간 때문에 불필요한 지연 표시가 생기지 않도록 했습니다.

## 3. 교육 불참·연기·정정
1. 수행자 계정으로 교육 업무 상세 → 실시 결과·등록 사유를 엽니다.
2. 불참·미실시 또는 연기를 선택하고 사유를 입력합니다. 사유 없이 저장할 수 없어야 합니다.
3. 참석·실시 완료를 선택할 경우 실제 실시일도 입력해야 합니다. 미래 날짜는 사용할 수 없습니다.
4. 관리자·팀장 계정으로 일정·마감 관리 → 직원 실시 결과·사유 → 의견 남기기에서 확인 의견을 작성합니다.
5. 수행자가 설명을 정정하면 관리자 확인이 초기화되고 과거 설명·확인 의견은 업무 상세 이력에 남습니다.
※ 실시 결과 기록은 업무 완료·결재와 별개입니다. 더 진행하지 않을 업무는 기존 업무 취소 또는 적절한 완료 절차로 처리하세요.

## 4. 일정 미등록 확인
1. 관리자·팀장으로 일정·마감 관리 → ‘일정 등록 대상’을 누릅니다.
2. 일정명·등록 담당자·예정 실시일과 등록 기한을 지정합니다. 확인용으로 기한을 조금 전 시각으로 지정할 수 있습니다.
3. 실제 업무가 연결되지 않고 기한이 지났다면 ‘미등록·확인 필요’로 표시됩니다.
4. 담당자가 업무를 등록한 뒤 대상 목록의 ‘연결·사유’에서 그 업무를 선택하고 설명을 남깁니다.
5. 등록이 필요 없어진 경우 관리자가 업무를 선택하지 않고 사유를 남겨 면제합니다. 일반 직원은 임의 면제할 수 없습니다.
※ 자동으로 모든 활동을 추정하지 않습니다. 지정된 등록 대상이 기준입니다. 반복 업무 자동 생성은 기존 정기 업무 기능을 계속 사용하고, 빠짐 확인이 필요한 의무 일정을 별도 지정하세요.

## 5. 마감 알림: 먼저 본인 한 명에게만 적용
1. 실제 알림 설정을 켜기 전에 본인 수행 테스트 업무 3개를 만듭니다.
   - 사전 알림: 마감일 오늘+3일
   - 당일 알림: 마감일 오늘
   - 지연 알림: 시작일·마감일 어제 (실제 업무 기간 조건 충족)
2. GUNSYSTEMS 관리자 → 마감 알림 설정에서 ‘알림 수신 대상 직원’을 본인(이상건)으로 선택합니다. 비우면 전체 직원이 대상입니다.
3. 사전 알림 3일, 알림 시작 시각은 현재 한국 시간 이하로 설정하고 ‘마감 알림 사용’을 켭니다. 처음에는 이메일·메신저를 꺼두고 내부 알림부터 확인해도 됩니다.
4. 정상 실행 중인 서버는 약 15초 간격으로 처리하지만 부하·통신 상황에 따라 더 걸릴 수 있습니다. 업무 알림과 일정·마감 관리 → 처리 기록에서 확인합니다. 같은 날 같은 업무·수신자·기한 알림은 중복 생성하지 않습니다.
5. 실제 이메일·메신저를 함께 검증하려면 해당 채널을 켜기 전에 별도의 새 테스트 업무를 준비한 뒤 사용 설정을 저장하세요. 이미 내부 알림만 생성한 건을 설정 변경만으로 재발송하지 않습니다.
6. 이메일은 직원별 하루 한 번 요약합니다. 같은 날 이미 요약을 보냈다면 새 테스트는 다음 날 또는 다른 본인 테스트 계정에서 확인하세요. ‘발송 서버 접수’와 실제 메일 수신은 구분합니다. 메신저는 해당 직원의 하이웍스 연결·알림 허용 상태가 필요합니다.
7. 테스트 종료 후 알림 사용을 끄거나, 실제 운영 기준을 확인한 뒤 전체 직원 범위로 전환합니다. 선택한 직원 외에 발송되는지 확인할 때는 수신 대상 설정을 먼저 점검하세요.

## 6. 마감 변경·완료·취소·결재
- 알림 생성 후 마감일 변경: 새 마감 기준으로 후속 알림이 계산됩니다. 대기 중 이메일·메신저는 발송 전 기한·수신자·현재 상태를 재확인해 부적합하면 제외합니다. 이미 받은 내부 알림은 과거 기록으로 남을 수 있습니다.
- 완료·취소: 이후 마감 알림이 생성되지 않아야 합니다.
- 결재 대기: 수행자 지연과 구분하며, 보고 시작일부터 검토 기한을 계산해 현재 단계의 미승인 결재자에게 안내합니다.
- 지속 지연: 설정 일수가 지나면 해당 담당자의 현재 직속 상위자에게 안내합니다. 직속 상위자 미지정·조회 권한 없음·수신 대상 제한이 있으면 대상에서 제외될 수 있습니다.
- 주말 보류: 토·일요일만 자동 보류합니다. 회사 공휴일·개인 휴가 연동은 이번 버전에 없습니다.

## 7. Google 캘린더 개선분
업무 상세 → Google 캘린더에 등록에서 등록 날짜(마감일 하루/수행 일정)와 표시할 내용(업무 일정/제목/제목과 설명)을 따로 선택하고 미리보기를 확인합니다. 수행 시간이 없으면 업무 기간 전체를 종일 일정으로 등록할 수 있습니다. 기존 등록 건은 기존 날짜 방식이 유지됩니다.

## 알려진 범위
- 캡스·근태 판정 없음. 고의성·불참을 자동 확정하지 않습니다.
- 등록 대상 지정·연결은 현재 수동 방식이며, 모든 반복 업무의 등록 의무를 자동 추정하지 않습니다.
- 마감 기준과 알림 시각은 현재 전사 공통 정책입니다. 업무별 임의 알림 규칙은 별도 확장 대상입니다.
- 각 현황 목록은 최근·우선 100건까지, 발송 처리 1회는 내부 처리 한도 내에서 순차 진행합니다.
- 실제 외부 채널 수신은 사용자 확인이 필요합니다. 불명확한 메일 결과는 자동 재발송하지 않습니다.
