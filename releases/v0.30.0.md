# v0.30.0 문서 그룹 권한 관리 기반

상태: v0.30.1로 보완하여 운영 반영. 최종 실제 검증 결과는 releases/v0.30.1.md 참조.

## 이번 범위
- SharePoint REST의 HasUniqueRoleAssignments와 RoleAssignments로 상속과 권한을 확인. Graph inheritedFrom과 invite는 사용하지 않음.
- 가장 가까운 고유 권한 상위를 찾아 폴더·문서함·설정된 사이트 경계를 구분.
- 저장 시 자동으로 상속을 분리하던 개인 일괄 대체 경로 제거.
- 상속 분리는 명시적 동작으로 현재 권한을 복사하고 하위의 별도 권한은 유지. 복원 전 상위 권한 표시와 재조회.
- 선택 그룹의 변경분만 추가·변경·제거. 다른 그룹과 개인 직접 권한 보존.
- 전용 사이트의 SharePoint 그룹을 생성하고 재직 직원을 여러 명 선택해 추가·제외.
- 기존 SharePoint 그룹의 구성원은 조회만 제공. Workhub에서 만든 그룹의 ID 참조만 DB에 저장하며 권한 원본은 SharePoint.
- 관리자 전용. 일반 직원의 문서 접근은 기존처럼 본인 Microsoft 위임 권한으로 확인.
- 사이트 단위 쓰기 잠금, CSRF, 일회용·10분 만료 미리보기, 외부 변경 감지, 변경 전후·사유·부분 실패 로그.

## 후속 범위
- 전체 폴더 권한 색인과 직원의 전체 접근 폴더 목록, 역할 템플릿, 여러 폴더 일괄 적용.
- 개인 권한을 그룹으로 이전, 퇴사·부서 이동 일괄 처리, 전용 이력 CSV.
- Entra 그룹 생성·구성원 변경은 이번 범위에 추가하지 않음. GroupMember.ReadWrite.All 요청 없음.
- 기존 권한은 자동 이전하지 않음. 코드 배포만으로 실제 직원 권한은 변경되지 않음.

## 검증 상태
- 관련 Django 105개 통과 후 기존 개인 대체 코드 제거와 상속 복원 시 관리자 보존을 보강. 최종 검사 별도 기록 예정.
- 로컬 IAB는 127.0.0.1 접근 불가, native Chrome도 화면 활성화 불가. 실제 화면 확인 완료로 기록하지 않음.
- migration 0057은 그룹 ID 참조 테이블만 추가. 직원·문서 ACL 변경 없음.
- 롤백 기준 488a710ea0e11f7473cc55186249bbefd7a3f9ff. 실제 권한을 변경했다면 앱 롤백만으로 SharePoint ACL이 복원되지는 않음.
