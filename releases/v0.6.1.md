## 문제와 수정

하이웍스 일정 구독 설정 HTML에 Referrer-Policy:no-referrer가 지정되어 있었다. HTTPS에서 Origin을 보내지 않는 브라우저는 같은 출처 Referer도 보내지 않아 정상 CSRF 토큰이 있어도 로그아웃 POST가 403으로 거부될 수 있었다. 업무 현황 등 다른 페이지는 같은 조건에서 로그아웃이 성공했다.

설정 HTML만 same-origin으로 변경한다. 외부 사이트로 Referer를 보내지 않는 동작은 유지하고, 서버가 같은 출처의 POST를 검증할 수 있게 한다. 실제 자격 토큰이 URL에 있는 iCal 다운로드 응답은 no-referrer를 유지한다. 로그아웃은 계속 CSRF로 보호된 POST이며 GET 로그아웃이나 외부 Origin을 허용하지 않는다.

## 검증

- 수정 전 재현: 전용 5개 검사 중 구독 페이지 로그아웃/헤더 검사 2개 실패(403 및 no-referrer), 다른 페이지·위조 요청 차단은 통과.
- 수정 후 HTTPS 연결 주소 발급→1회 표시→해시 보관→iCal 읽기→주소 폐기와 로그아웃을 포함한 관련 40개 검사 통과 (24.995초). 다른 업무/Google 연결/기간 보고/관리자 페이지에서 세션 종료 및 이후 업무 접근 차단, 잘못된 토큰·외부 Origin·GET 로그아웃 차단 확인.
- DB migration·계정·권한·구독 토큰 변경 없음.
- 운영 health: version=0.6.1, commit=0c44b70, status=ok. 실서버의 관리자 설정 view 조회(RequestFactory, 세션 저장/발급 없음)에서 status=200, Referrer-Policy=same-origin, no-store, 새 ‘하이웍스 일정 연결’ 제목 확인. 이 호출 당시 실제 구독 0건이며 운영 주소를 대신 발급하지 않음.
- 실제 사용자 브라우저의 수정 후 발급/로그아웃 재시험 및 하이웍스 수신 검증과 위 자동/실서버 조회 검증을 구분한다. 수정 전부터 열려 있던 화면은 새로고침해야 변경된 응답 정책이 적용됨.

## 화면과 연동 방향

- 사용자 요청대로 메뉴·제목·도움말·Google 설정의 이동 링크를 ‘하이웍스 일정 연결’로 통일.
- Workhub → 하이웍스 단방향. 최초 1회 외부 캘린더 연결 후 실제 생성된 본인 담당/참여 업무를 자동 표시. 반대 방향으로 일정 가져오기는 없음.
- 회사 직원의 개인 업무 연결은 본인 직원 계정에서 진행하도록 관리자 운영 계정에 안내. 관리자 계정만으로 전사 업무를 외부에 자동 전송하지 않음.
- 하이웍스 외부 캘린더 표시는 공식 매뉴얼로 재확인. 공개 서비스 API 목록에서 자체 일정 직접 생성 API는 확인하지 못했으며, 직접 쓰기 API를 구현했다고 안내하지 않음.
- 회사 하이웍스 실제 개인 캘린더 연결·갱신·수정/취소 수신은 아직 미검증. 테스트 DB의 자동 검사와 실제 외부 연동 완료를 구분함.

공식 연결 방법: [하이웍스 외부 캘린더 구독](https://customer.gabia.com/manual/hiworks/1340/23784), [공개 개발자 문서](https://developers.hiworks.com/docs).
