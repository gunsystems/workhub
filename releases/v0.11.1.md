# Workhub v0.11.1 계정 전환 OTP 오류 수정
2026-11-10 · Asia/Seoul

## 원인과 수정
기존 사용자 세션이 있는 상태에서 다른 계정의 비밀번호를 제출하면 세션 키만 변경하고 기존 인증 사용자를 유지했습니다. OTP 대기 계정과 인증 사용자가 섞여, 등록된 직원의 기존 OTP 입력 대신 이전 계정의 QR 등록 화면이 열릴 수 있었습니다. 수정 전 자동 검사로 이 오류를 재현했습니다.

- 새 로그인 제출은 기존 로그인·OTP 인증·이메일 활성화 등 세션 상태를 비우고 독립된 인증 시도로 시작합니다.
- 잘못된 비밀번호를 제출했을 때도 이전 계정이 로그인 상태로 남지 않습니다.
- 기존 버전에서 만들어진 혼합 세션은 새 QR을 만들지 않고 로그인부터 다시 진행하게 합니다.
- OTP 대기 만료 시 계정과 시각을 함께 정리합니다.
- 인증 중인 이메일/아이디 표시, POST·CSRF 보호된 다른 계정으로 로그인 버튼 추가. OTP 복구 중에도 계정 전환 가능.
- 기존 계정·비밀번호·등록된 OTP 장치·복구 정보는 수정/삭제하지 않습니다. 다른 로그인 세션을 일괄 종료하지 않습니다. 새 로그인 시 해당 브라우저 세션만 교체합니다.

## 검증
수정 전 재현 검사 실패를 확인하고 수정 후 인증·복구·HTTPS CSRF·로그아웃 관련 58개 통과. 추가 복구 중 전환 검사를 포함한 전체 Linux CI 진행 예정. 운영 배포 대기. migration 없음.

## 확인 방법
1. 현재 열려 있는 로그인/QR 화면은 새로고침한 뒤 다른 계정으로 로그인을 누르거나 /login/ 에서 다시 시작합니다.
2. 전환할 계정의 이메일과 비밀번호를 입력합니다.
3. 기존 OTP가 등록된 계정은 QR 등록 대신 2차 인증 화면과 해당 이메일/아이디가 표시되어야 합니다.
4. 기존 Google OTP 6자리로 인증한 뒤 화면 상단의 이름·부서가 전환한 계정인지 확인합니다.
5. 다시 로그아웃 또는 30분 무활동 후 다른 계정으로 같은 순서를 확인합니다. 기존 OTP를 삭제하거나 새 QR을 등록하지 마세요.

※ 실제 운영 계정의 비밀번호·OTP로 대신 로그인하는 시험은 하지 않습니다. 별도 테스트 데이터베이스에서 두 계정의 인증 흐름을 검증합니다.
