# Workhub v0.12.0 — 업무별 자료 관리와 Google Drive 저장소

업무·업무협조 요청·프로젝트에 참고 자료, 진행 자료, 결과물, 점검확인서를 등록합니다.
업무협조 요청을 처음 작성할 때 참고 파일을 함께 전달할 수 있습니다.

- 실제 파일은 회사 공유 드라이브에 저장합니다. 직원은 Workhub에서 파일명을 눌러 내려받습니다.
- 파일당 20MB, 업무·요청·프로젝트별 활성 자료 100개. PDF·Office·텍스트·이미지·ZIP 지원.
- 큰 자료는 이름을 붙인 외부 링크로 등록합니다. 링크 원본 저장소의 권한은 별도로 관리합니다.
- 보고서의 새 첨부도 Drive에 저장하며 기존 10MB 제한·제출 버전 정책을 유지합니다.
- 기존 로컬 보고서 파일은 원래 위치에서 계속 내려받습니다. 이번 배포에서 강제 이관하거나 삭제하지 않습니다.
- 다운로드마다 연결된 업무의 현재 열람 권한을 확인합니다. 공개 링크·직원별 Google 로그인은 사용하지 않습니다.
- 자료 보관은 목록에서 숨기는 처리입니다. 원본과 사유·시스템 로그를 유지하며 파일 영구 삭제는 제공하지 않습니다.
- 관리자 전용 ‘업무자료 저장소’에서 파일 업로드 없이 연결과 파일 추가 권한을 확인합니다.
- 새 화면의 도움말과 흐름도를 추가합니다.

## 서버 설정

Render Secret File: `workhub-drive.json` (내용은 Git·채팅에 저장하지 않음).

| 환경변수 | 설정 |
|---|---|
| GOOGLE_DRIVE_CREDENTIALS_FILE | /etc/secrets/workhub-drive.json |
| GOOGLE_DRIVE_SHARED_DRIVE_ID | 관리자가 지정한 공유 드라이브 ID |

공유 드라이브의 콘텐츠 관리자 멤버인 서버 전용 서비스 계정으로 접근합니다.
프로젝트 IAM Owner/Editor, 도메인 전체 위임, 공개 공유 권한은 필요하지 않습니다.

## 적용과 롤백

마이그레이션 0030은 WorkDocument 테이블을 추가합니다. 운영 SQLite 변경 직전
`/var/data/backups/workhub-pre-v0120-*.sqlite3` 백업을 만들고 무결성을 검사합니다.
기존 테이블의 데이터와 로그인·OTP 정보는 변경하지 않습니다.
이전 앱으로 롤백하면 추가 테이블·클라우드 파일은 보존됩니다. Drive 파일을 담은 보고서가 생긴 이후에는
이 저장소 코드를 포함하는 버전으로 롤백해야 해당 첨부를 계속 열람할 수 있습니다.
버전 0.11.1에는 Drive 파일 처리 기능이 없으므로 해당 버전으로 단순 복귀하면 새 첨부 다운로드는 지원되지 않습니다.

## 확인

- 관리자: 업무자료 저장소 → 연결 확인. 성공 시 드라이브 이름과 파일 추가 권한 표시.
- 직원: 업무 상세 → 자료 추가 → PDF 등록 → 파일명 클릭 → 다운로드.
- 요청자: 업무협조 요청 작성 → 참고 파일 첨부 → 등록 후 원본 요청 업무자료 확인.
- 프로젝트: 업무자료에서 결과물 또는 외부 링크 등록.
- 자료 등록자/관리자: 보관 사유 입력 → 목록에서 숨겨짐, 시스템 로그 유지.
- 무관한 다른 부서 계정: 파일 URL을 직접 입력해도 접근 불가.

아직 제공하지 않는 기능: 문서 온라인 편집, 파일 내용 검색, 자동 버전 병합, 바이러스 검사,
미리보기, 기존 로컬 첨부 자동 이관. 자료는 연결된 업무를 기준으로 찾습니다.
