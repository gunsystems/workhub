# 업무 요청·협조 요청 설계 참고 사례
2026-11-10 공식 문서 조사. 아래 반영 내용은 Workhub 요구에 맞춘 설계 판단이며 해당 서비스의 모든 기능을 구현했다는 의미가 아닙니다.

| 공식 사례 | 참고한 방식 | Workhub 반영 |
|---|---|---|
| [Asana Project intake](https://help.asana.com/s/article/project-intake) | 표준 양식·요청 종류·요청 팀·분류와 초기 검토 담당자 | 직접 업무 요청과 팀 협조 요청 분리, 고객사·솔루션·인원·희망 기간·회신 기한 양식 |

| [Asana Workload](https://help.asana.com/s/article/portfolio-workload-and-universal-workload) | 여러 프로젝트의 업무 분포를 보고 인력 배분 판단 | 희망 기간에 겹치는 조회 가능 팀 업무 표시, 역할·개인 투입 기간 기록 |

## 이번 설계 판단
- 팀 간 요청은 어느 직원이나 작성할 수 있으나 인력 확정은 수신 팀장·부서 관리자·임원에게 제한합니다.
- 팀장 공석 시 대행자는 접수·협의만 수행하고, 확정 배정은 관리자·임원이 담당합니다.
- 한 협조 요청은 하나의 공동 수행 업무에 연결해 원본 요청·결재·보고가 갈라지지 않게 합니다.
- 수행 업무 완료와 요청자 결과 확인은 별도입니다. 추가 지원은 완료 업무를 덮어쓰지 않고 연결된 새 요청으로 만듭니다.
- 업무량은 현재 날짜 중복 정보입니다. 휴가·인당 가용시간·필요 기술을 자동 판단하거나 인력을 자동 선정하지 않습니다.
- 자료 저장소 통합·자동 배정·개인별 캘린더 투입 구간은 별도 확장 범위입니다.
