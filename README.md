# GUNSYSTEMS Workhub

직원과 부서의 업무를 월·주·일 캘린더에서 관리하는 Django 애플리케이션입니다.

## 개발 시작 (Python 3.12)

```bash
cd /workspace/workhub
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate --noinput
.venv/bin/python manage.py createsuperuser
# 선택: 빈 개발 DB에만 예시 직원과 업무 생성
.venv/bin/python manage.py seed_demo
.venv/bin/python manage.py runserver 127.0.0.1:8000 --noreload
```

로그인은 `/login/`에서 합니다. 관리자에서 부서, 직원, 사용자 계정을 등록합니다.
최상위 관리자(superuser)는 전사 업무와 계정·부서·직원 설정을 관리합니다.
부서 관리자는 자기 부서 업무를 조회·등록·수정하고, 일반 직원은 자기 부서 업무 조회 및 본인 업무 등록·수정만 가능합니다.
로그인 계정과 직원 정보가 연결되지 않으면 접근이 차단됩니다. Django staff나 개별 모델 권한만으로 부서 제한을 우회할 수 없습니다.

기본 부서는 영업팀·보안기술팀·경영지원팀입니다. 기존 개발팀·기술지원팀의 `(예시)` 직원만 보안기술팀으로 이동합니다. 실제 직원이 있는 기존 부서는 보존합니다.

## 직원 계정과 권한 설정

1. 최상위 관리자 계정으로 `/admin/`에 로그인합니다.
2. Users에서 일반 사용자 계정을 생성합니다. 일반 계정에 Superuser status는 부여하지 않습니다.
3. Employees에서 직원의 이름·부서를 지정하고 로그인 계정을 연결합니다.
4. 업무 권한을 `일반 직원` 또는 `부서 관리자`로 지정합니다.
5. 부서 관리자도 Django admin은 사용할 수 없으며, 캘린더의 업무 등록·수정 화면을 사용합니다.

한 계정은 한 직원에만 연결됩니다. 직원 부서 변경은 그 직원에게 배정된 기존 업무의 조회 범위도 변경합니다. 관리자에서 소속 변경 시 참고하세요.

## 기본 기능

- 월·주·일 캘린더, 이전/다음 기간 및 오늘 이동
- 직원·부서·진행 상태 필터 (함께 적용 가능)
- 업무 등록, 상세 조회, 수정
- 담당자와 소속 부서, 예정/진행 중/보류/완료, 중요도, P1~P4 우선순위, 시작일과 마감일
- 캘린더 내 우선순위 순 정렬, 여러 날 업무의 날짜별 표시
- 기한 초과 및 3일 이내 마감 업무 별도 목록 (전체 기간, 현재 필터 기준)
- 완료 업무는 마감 경고에서 제외, 날짜는 Asia/Seoul 기준
- SQLite 파일로 데이터 영구 저장, CSRF 및 로그인 접근 보호

중요도는 업무 영향도, 우선순위는 실행 순서입니다. 부서는 담당 직원의 현재 소속을 따릅니다.
예시 데이터는 `[예시]`와 `(예시)`로 표시되며 실제 직원이나 고객 업무가 아닙니다.

## 현재 범위

로컬 개발용 기본 버전입니다. 실제 사내 운영 전 변경 이력, 로그인 시도 제한, 백업, PostgreSQL 및 운영 배포 구성을 검토해야 합니다.
개발 서버는 로컬에만 바인딩합니다. 배포 시 `DEBUG=0`, 안전한 `SECRET_KEY`, `ALLOWED_HOSTS`를 설정하고 운영 WSGI 서버를 사용하세요.
저장소는 기존 `/workspace/workhub`를 사용하며 새 Git worktree를 만들 필요가 없습니다.

## 업무수행 관리

- `/dashboard/?scope=mine`: 내 업무, 미착수·기한 초과·3일 이상 미보고·검토 대기, 받은 업무별/종합 피드백과 본인 수행 현황
- `/dashboard/`: 최상위 관리자의 전사 관리 또는 부서 관리자의 팀 관리. 일반 직원은 본인 화면으로 제한
- `/`: 기존 월·주·일 캘린더. 부서 직원의 점수와 개인 종합 피드백은 동료에게 공개하지 않음
- 직원별 이름을 클릭해 해당 직원 업무를 필터링하고 종합 피드백·개선 계획 작성

### 수행 흐름

1. 업무 등록: 최초 마감일을 기준 마감일로 보존합니다.
2. 담당 직원이 진행률·수행 내용·다음 계획과 지연/장애 사유를 보고합니다. 100% 진행은 완료 보고 단계에서 처리합니다.
3. 담당 직원이 결과 및 결과물 위치를 완료 보고하면 `검토 대기`가 됩니다.
4. 부서 관리자는 자기 부서 일반 직원, 최상위 관리자는 중간관리자 포함 전 직원의 결과를 승인하거나 보완 요청합니다. 누구도 본인 업무를 스스로 승인하거나 평가할 수 없습니다.
5. 승인 시 평가 근거와 0~100점 결과 평가를 기록합니다. 보완 요청 시 직원이 다시 보고합니다. 모든 이전 보고와 피드백은 보존됩니다.

업무 수정으로 완료/검토 대기를 직접 지정할 수 없습니다. 검토 대기·완료 업무는 일반 수정이 잠기며, 마감일 변경은 관리자만 할 수 있고 사유가 필요합니다. Task Django 관리자 화면은 이력 우회를 막기 위해 조회 전용입니다. 업무 등록·수정은 Workhub 화면을 사용하세요.

### 점수 산식 v1

선택한 월에 **최초 마감일**이 있는 업무를 대상으로 합니다. 월별 평가는 현재 데이터를 기준으로 다시 계산하며 확정된 인사평가 등급이 아닙니다.

- 대상(분모): 최초 마감일이 어제 이전이거나 실제 완료 기록이 있는 업무 중 검토 대기와 완료 시점 미상 과거 업무를 제외
- 완료율: 승인 완료 건수 / 대상 건수 × 100
- 기한 준수율: 최초 마감일까지 완료 보고하고 승인된 건수 / 대상 건수 × 100
- 결과 평가: 승인 시 입력한 평가 점수의 산술 평균
- 종합 점수: 기한 준수율 × 0.4 + 완료율 × 0.3 + 결과 평가 × 0.3 (소수 첫째 자리)

완료 기준은 승인된 **완료 보고 시각**입니다. 관리자 검토 대기로 발생한 지연을 직원 지연으로 가산하지 않습니다. 최초 마감일을 변경하여 이전 지연을 지울 수 없습니다. 평가나 대상이 없으면 `—`로 표시하며, 기존 업무의 알 수 없는 완료 시각·결과 평가는 생성하지 않습니다. 표에 분모·완료·기한 준수·평가 건수 및 제외 건수를 표시합니다.

중요도/난이도와 외부 대기 사유는 자동 가중하지 않습니다. 지연 사유·업무량과 함께 검토해야 합니다. 직원 소속·업무 담당자를 변경하면 조회 범위와 현재 담당자 기준의 집계도 변경됩니다. 과거 부서/담당자 기준의 고정 평가표는 별도 기능입니다.

### 누락·관리 필요 기준

- 미착수: 시작일이 지났지만 예정 상태
- 장기 미보고: 시작일 또는 직전 직원 보고 이후 3일(달력 일수) 이상 진행·완료 보고 없음. 관리자 피드백은 직원 보고를 대신하지 않음
- 보고 공백 이력: 직원이 보고할 때 직전 보고/시작일과 3일 이상 간격이면 해당 보고에 공백 일수 기록
- 관리 필요: 선택 월의 지연 업무 2건 이상, 보고 공백 2회 이상, 현재 미보고 업무 2건 이상 또는 미착수 2건 이상

점수와 별도로 현재 미착수/미보고 및 반복 지연·보고 공백을 표시합니다. 업무 목록의 현재 상태는 전체 기간이며 평가표만 선택한 월을 사용합니다. 등록 자체가 안 된 업무를 자동 탐지하는 기능이나 반복 업무 자동 생성, 이메일/메신저 알림은 포함하지 않습니다.
